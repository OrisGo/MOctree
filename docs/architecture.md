# 结构设计

状态：geom、objects 和根包入口已实现；其余目录和未来类型为规划示意。更新日期：2026-10-21。

## 1. 设计原则

共享几何与基础设施；对象索引和点云索引分别设计；静态与动态使用独立类型；存储精度与外部 ABI 显式表达。

首版只创建实际需要的包，不创建空的未来实现，不提前设计一个覆盖所有场景的万能 `Octree[T]`。

## 2. 目标目录与职责

```text
Octree/
├── moon.mod
├── moon.pkg
├── geom/                    # 公开几何类型和谓词
├── objects/                 # 首版：静态 AABB 对象索引
│   └── dynamic/             # 后续：动态对象索引
├── points/                  # 后续：静态点云索引
│   └── dynamic/             # 后续：动态点云索引
├── internal/                # 实际证明可共享的私有基础设施
├── adapters/                # JS/WASM 宿主接口与缓冲管理
├── examples/
├── benchmarks/
└── docs/
```

目录树表示职责划分，不是完整的 MoonBit 配置清单。创建包时再补齐相应包配置与目标设置。

| 边界 | 所有的职责 | 不承担的职责 |
|---|---|---|
| 根包 | 精简入口与有意选择的公开导出 | 包揽所有算法、默认实例化动态成本 |
| geom | 坐标、AABB、射线与数值谓词 | 引擎实体、DOM、渲染资源 |
| objects | ID + AABB 快照、构建、只读查询 | 点云近邻语义和动态维护 |
| objects/dynamic | 对象定位与动态更新 | 改变静态索引内部存储 |
| points | 点坐标存储及点查询算法 | 将每个点长期包装成完整 AABB |
| points/dynamic | 点更新和动态维护 | 自动继承对象树的全部实现 |
| internal | 已确认可复用的检查、编号或辅助算法 | 拥有用户需要构造和检查的公开具体类型 |
| adapters | 数据编码、批量调用、实例与缓冲生命周期 | 向调用者泄露内部节点布局 |

依赖从适配层和示例指向公开索引，再指向几何及内部工具。核心不能反向依赖适配层。对象与点云包不因“都是八叉树”而互相依赖。

原根目录 `geom.mbt` 的 Vec3 已迁入公开 geom 包，由根包重新导出；原有 `@octree.Vec3::new` 和 `origin` 的使用方式保留。源类型归属改变，不承诺二进制 ABI 兼容。

## 3. 静态对象索引

概念上分为：

1. 输入校验：几何合法性、ID 和容量规则、根包含关系。
2. 构建临时状态：分区与节点生成所需工作空间。
3. 最终只读存储：对象 ID、坐标、节点关系和对象归属。
4. 查询工作区：可复用的遍历空间。
5. 输出缓冲：命中 ID 及每次查询的结果状态。

构建临时状态不应无故保留到最终索引。对象和节点用整数索引关联，对象外部 ID 不作为物理存储位置。

节点需要表达自身边界、孩子关系和本节点存放的对象。按需创建孩子，不因逻辑上有八个象限就创建八个空节点。边界可以用中心和半边长表达，不要求与对象 AABB 使用相同布局。

当前使用条目数组、节点数组和对象索引顺序数组。节点通过直属孩子的起始编号、数量和位掩码表示稀疏孩子，避免每节点八个固定引用；节点内对象通过顺序数组的区间访问。构建先为全部非空直属孩子分配连续编号，再递归处理，节点编号顺序不等于公开 DFS 遍历顺序。

构建临时分桶不保留在最终索引中，但有界递归期间可能同时保留多层临时数据；其峰值待第二阶段测量。后续是否改为分离数组或更紧凑布局，由测量决定。不把“数组节点池”描述成所有后端都连续、零拷贝或零分配。

## 4. 对象与点云的复用边界

| 内容 | 对象索引 | 点云索引 |
|---|---|---|
| 条目 | ID + 六坐标 AABB | ID + 三坐标点 |
| 归属 | 内部节点和叶子均可存对象 | 通常由叶子存点 |
| 查询 | AABB 相交、射线候选 | 区域、半径、kNN |
| 关键剪枝 | 查询几何与节点边界 | 点到节点的距离下界 |

优先共享几何谓词、八分区编号规则、容量检查和可比较的统计口径。节点布局、构建算法和遍历器不预先统一；只有出现实际重复并确认语义相同后再提取。

用零尺寸 AABB 对照点查询可作为测试手段，但不能替代专门的点云存储。点云近邻算法不能直接沿用对象射线查询逻辑。

## 5. 动态写入扩展

StaticObjectIndex 已实现；DynamicObjectIndex、StaticPointIndex、DynamicPointIndex 仍为概念名称。

静态与动态类型尽量共享查询参数、几何谓词、结果完整性和统计语义，不要求共享内部存储。不使用一个运行时 `dynamic=true` 开关迫使静态用户承担所有动态字段。

动态类型按需要引入：

- ID 到存储位置的定位机制。
- 对象或点的插入、删除、几何更新。
- 空闲位置复用、节点回收和重定位。
- 明确的根外更新行为与容量失败行为。

动态实现首先可以要求更新和查询不交错，不需要首版预置并发快照或共享内存。是否合并节点、何时重建、是否采用 loose 边界，需要单独测量。

预留“静态索引创建动态副本”和“动态索引生成紧凑只读快照”的转换方向；它们是可能进行复制或重建的显式操作，不承诺零拷贝、相同节点编号或首版提供。

## 6. 精度扩展

区分输入精度、内部存储精度和计算精度。首版均以 Double 为基线。

后续单精度必须落实到实际坐标存储；仅接受单精度输入后转换成 Double 保存，不算完成该扩展。

设计要求：

- 将坐标存取、几何谓词和转换规则集中到清晰边界，避免散落硬编码。
- 倾向明确的单精度/双精度类型或构建入口，避免每节点精度标签和热路径反复分派。
- 暂不决定用泛型、代码生成还是专门实现复用；引入第二种精度时结合编译结果、维护成本和基准选择。
- ID、节点关系和其他元数据不随坐标精度自动减半，不承诺整体内存减半或必然提速。
- 降低存储精度不自动规定计算也必须使用同样精度；精度组合应有测试与性能依据。

双精度 AABB 转单精度若需保持保守包含，应对下界向下、上界向上取整；查询几何的转换也必须遵守明确的保守规则。超出单精度可表示范围的处理需定义，不允许静默产生无效边界。最终可通过原始高精度几何进行精确复核。

点坐标量化会改变点的位置和距离排序。单精度点云查询以其表示的数据为准，不能承诺与原始双精度数据得到完全相同的 kNN。

## 7. 查询工作区与遍历

查询工作区 Workspace 与索引分离，调用者可复用；结果缓冲使用独立固定数组。当前工作区保存固定容量迭代 DFS 栈，要求 `1 + 7 × 实际深度` 个节点索引，开始操作前校验容量，不在热路径扩容。

层级遍历提供只读信息，不能借此修改节点或索引拥有的几何快照。节点编号不保证跨重建、转换或动态更新稳定。稳定外部身份依赖对象或点 ID。

统计字段应区分结构统计和单次查询统计，避免把所有计数藏成索引内唯一的可变全局状态。

### 纯 MoonBit 批量执行

2026-10-23：objects/batch.mbt 提供 `BatchQuery[T]`、`BatchError` 与两个批量查询入口。
批次先校验全部输出区间，并对非空区间按起点排序检查重叠，再检查工作区容量。
随后按原始请求顺序复用现有单条查询遍历器，不复制索引、不重复实现几何谓词。
几何构造错误通过请求的 Result 保留，逐条报告也使用 Result；批次结构错误整体抛出。
临时区间数组和报告数组随批次数量增长，未作零分配承诺。

## 8. JS/WASM 适配层

核心查询首先面向纯 MoonBit 数据。适配层定义独立、可版本化的批量数据协议，说明坐标精度、ID 编码、数量、偏移和结果状态。

每次批量查询必须能定位各自的结果范围及完整性。输入复制与结果有效期要明确，不能暴露一个未经生命周期约束的内部视图。

wasm 与 wasm-gc 可以使用不同的传输实现，但必须保持相同查询语义。单精度扩展时增加明确格式，而不是悄悄改变既有 Double 接口的含义。

本轮不冻结二进制布局、导出函数名称、JS TypedArray 组合或内存句柄协议。
