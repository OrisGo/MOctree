# AABB 子树整体命中优化验收

2026-10-25。从最新 `origin/main`（`03a0ab2`）创建独立分支，基线模块在修改源码前构建保存。
优化增加每节点一个 Int32 子树对象数，复用 DFS 连续对象顺序区间；包含节点时准确累计命中，
只写剩余容量允许的 ID，跳过后代剪枝和对象谓词。没有改变公开 API、射线语义、结果完整性
或统计口径；visited_nodes/tested_objects 的数值随实际工作减少。

## 环境与方法

AMD Ryzen 7 8845HS（16 逻辑 CPU），主机内存 24,429,539,328 字节；
Linux 7.2.11-200.fc44.x86_64，Node.js v22.23.1 / V8 12.4.254.21-node.56，
moon 0.1.20261020 (2284bd2)，moonc v0.10.16+b1a0e846e，prek 0.4.14。
后端为 release stripped wasm，包含 linear 适配传输和输出复制。本轮未重测浏览器性能。

[复现命令及测量边界](../benchmarks/subtree/README.md)；
[完整原始数据](../benchmarks/results/2026-10-25-aabb-subtree-node.json)包含环境、模块及源码哈希、
162 行查询测量（每行 100 个样本）、18 组构建测量（每组 9 个独立实例）、18 组资源快照。
种子 20261025，1 千/1 万/10 万对象，三类分布、局部/子区/全根三种负载，
count/cap64/all 三种输出模式。每批 8 条查询，20 次预热；前后版本逐轮轮换顺序。
计时期间不运行编译、测试或 profiler。这里是单机单轮观测，不提供稳定尾延迟保证。

全根查询每批准确命中 800,000 个对象。优化后 visited_nodes=8、tested_objects=0，
count 写 0，cap64 写 512，all 写 800,000；前两者仍准确报告截断。
内部子区不是总能跳过所有其他节点：闭合边界相切时邻居节点也需判断，跨分割面对象仍在父节点检查。
例如均匀分布子区查询的 visited_nodes 从 39,534 降至 15,283，tested_objects 从 186,493
降至 88,224；聚簇对应从 1,049/100,000 降至 52/0。

全重叠对象跨根分割面，局部/子区查询不能走整体包含路径，仍实际测试 800,000 次。
其中子区 count p50 从 17.6343 升至 18.8969 ms（约 7.2%），同负载其他模式有小幅下降；
不能将波动解释为所有场景必然提速。另有 1 千均匀局部 count 从 0.0227 升至 0.0253 ms
（约 11.5%，绝对约 2.6 μs）。包含检查本身有成本，小负载也容易受宿主噪声影响；未做统计显著性推断。
完整输出仍需读取/复制 ID，all 模式还预留并复制 8N 个槽位，不能由 count 的倍数推断全部查询收益。

## 构建与内存

10 万对象构建 p50（ms），包含输入复制、校验、构建及工作区：

| 分布 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| uniform | 89.525 | 90.120 | +0.66% |
| cluster | 70.418 | 71.942 | +2.16% |
| overlap | 55.593 | 53.254 | -4.21% |

每节点逻辑上新增一个 Int32，无额外对象数组或构建后处理遍历。实测 10 万均匀对象
构建后线性容量前后均为 45,088,768 字节，聚簇和重叠均为 22,544,384 字节。
三种输出模式及释放后容量仍相同。容量增长粒度和分配器保留空间会掩盖字段增量，
不能据此宣称零内存成本；也不能把它称为稳态存活字节或活跃堆峰值。
本轮未测进程 RSS、构建中活跃堆峰值、GC 次数或受限设备。
模块从 29,056 增至 29,454 字节（+398 字节）。

## 验证

- 八类核心分布 × 三档节点预算；新增逐节点边界查询，与暴力扫描比较准确总数、
  零容量/限量/恰好填满/多余容量、ID 成员和唯一性、未写区域哨兵。
- 结构不变量测试检查直属对象与孩子子树区间连续、子树计数、包含关系和单归属。
  显式测试内部节点跨面对象、整体包含孩子及相切兄弟的统计值。
  原有空根、退化/极端坐标、预算/深度/数值停止和射线测试继续通过。
- `moon fmt`、`moon check --target wasm` / `wasm-gc`；
  `moon test` 的 wasm、wasm-gc、JS 各 29 项通过。
- `moon info --target wasm`，生成公开接口无变化。
- linear debug/release 集成通过（八类暴力对照、三档预算、双后端统计一致、1K/10K/100K 内存增长）；
  prototype wasm/wasm-gc 集成通过。
- 基准两个模块各 30 项共同域验收通过，全部计时组合在计时前通过独立 JS 暴力扫描。
- 暂存后 `prek run`、`git diff --cached --check`、全仓跟踪 JS 语法与本地文档链接检查通过。

本轮只验收该优化，不将其视作 M2、浏览器跨设备或完整内存峰值验收完成。
