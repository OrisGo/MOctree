# 项目方案与扩展路线

状态：已确认方向，尚未实现。更新日期：2026-10-21。

## 1. 定位与已确认决策

面向浏览器等 WASM 运行环境，提供资源可测量、结果完整性明确、支持批量调用的三维空间索引。

已确认：

1. 首版支持 AABB 对象索引，采用批量构建和只读查询。
2. 后续需要支持动态写入，包括插入、删除及几何位置更新；首版通过显式重建更新数据。
3. 首版暂定 `Double`；后续需要提供真正使用单精度坐标存储的版本。
4. 后续支持点云索引，逐步提供半径及 kNN 等点查询能力。
5. 对象索引与点云索引分别设计，静态与动态类型独立；共享适合复用的几何与基础设施。

WASM-first 是工程方向。动态 loose octree、Morton 排序和数值泛型都是候选实现技术，不是已确定的要求。

## 2. 应用场景与数据模型

首个验证场景是浏览器三维场景的查看、选择和区域筛选，兼顾桌面与中低端移动设备。

首版每个条目由对象 ID 和三维轴对齐包围盒 AABB 组成。应用管理真实模型、网格和渲染资源，索引管理几何快照。ID 与内部节点编号、数组位置分离。

查询精确到规定的包围盒谓词。对真实模型而言，结果仍是候选集合：射线穿过包围盒不代表击中了网格。精确模型相交由应用完成。

零尺寸 AABB 可以表示点，但首版不因此宣称提供点云 kNN、降采样或专用点云索引。

静态或低频变化的数据用于控制首版范围，不代表已经证明它们在 MoonBit 生态中占多数。

## 3. 首版范围

| 必须交付 | 要求 |
|---|---|
| 批量构建 | 固定根立方体、双精度坐标、容量校验 |
| AABB 相交查询 | 明确几何边界语义，与暴力扫描对照 |
| 射线候选查询 | 接受明确的射线参数区间 |
| 调用者提供结果缓冲 | 可复用，容量不足不得伪装成完整结果 |
| 批量查询 | 减少宿主与 WASM 之间的调用次数 |
| 只读层级遍历 | 不暴露可修改内部节点 |
| 统计 | 对象数、节点数、深度、节点访问量及容量使用 |
| 错误与完整性状态 | 区分非法输入、构建容量问题和结果不足 |
| WASM 适配与示例 | 批量输入、紧凑结果、清楚的缓冲所有权 |
| 文档、测试和基准 | 可复现的数据、环境及已知限制 |

`build`、`query_aabb`、`query_ray_candidates`、`query_into` 等名称目前仅表达操作意图，不是已冻结的 API 签名。

首版不做：

- 任意增删改、自动扩根、动态树内部维护。
- 专用点云索引、kNN、球形查询、降采样。
- 视锥查询、完整碰撞对管理、精确三角形碰撞。
- 多线程、GPU 后端、磁盘持久化格式。
- 概率占据地图、大规模点云流式系统、二维游戏索引。
- 为多个精度或多种布局同时维护生产后端。

## 4. 首版树结构

以普通、单归属对象八叉树作为正确性与资源测量基线：

- 使用固定根立方体和有上限的划分深度。
- 对象的整个 AABB 能放进某个子节点时才下沉；跨分割面的对象留在父节点。
- 每个对象只存一次，查询必须检查内部节点自身存放的对象。
- 达到深度、节点预算或数值上不能继续细分时，停止划分并局部扫描。
- 根外对象明确报错，不裁剪、不静默丢弃。
- 使用数组和整数索引，按需创建子节点；具体数组布局通过测量决定。
- 构建后可以整理节点与对象索引，不强制 Morton 排序。

停止细分不应损害结果完整性。分裂阈值和“有效细分”的具体规则需在实现前确定，见 [接口契约](contracts.md)。

## 5. WASM-first 工程要求

### 内存与调用

- 分别报告构建峰值和稳态内存，包含输入、索引、临时空间、结果缓冲及跨语言副本；说明测量覆盖范围和无法观测的部分。
- 提供对象数、节点数和深度限制。节点上限不等于整个运行时的精确字节上限，也不保证不会出现运行时内存耗尽。
- 查询尽量复用结果和遍历工作区，测量热路径分配情况。
- 核心不依赖 DOM、WebGPU、Three.js 或特定 WASI 宿主。
- 适配层优先批量输入、返回 ID 和紧凑结果，不逐命中回调 JS。
- 明确输入复制、所有权、缓冲生命周期及失效条件，不把内部对象布局当稳定 ABI。
- 单线程可用，Worker 为可选部署方式，不要求共享内存。

### 后端与数值

首版分别验证 wasm 和 wasm-gc 的端到端路径，JS/native 用于兼容与对照。相同源码和数组节点池不代表各后端具有相同布局、内存成本或零拷贝能力。

首版暂用 Double，并建立可用于后续单精度比较的误差与内存基线。不能通过接受漏查来换取内存节省。所有数值边界语义应形成测试。

## 6. 验收与基准

正确性以暴力扫描为参照，至少覆盖随机分布、聚簇、近似平面、细长对象、巨大跨节点对象、全部重叠、重复位置、零尺寸和边界相切。另测非法输入、预算停止细分、空索引、缓冲不足及批量结果边界。

性能计划比较暴力扫描、网格和静态 MoonSTRtree。接入基准前核实其版本、三维查询语义和支持后端，并统一数据、谓词和输出要求；不可把语义不同的结果直接比较。

至少报告：

- 模块压缩体积，注明压缩方式；首次可查询时间，注明起止点。
- 构建时间、构建峰值和稳态内存。
- 包含数据传递的端到端查询延迟及 p50、p95、p99。
- 访问节点数、测试对象数、命中数及退化情况。
- 设备、浏览器、编译器版本、后端、构建模式、数据种子和测量方法。

初始规模档位为 1 千、1 万、10 万对象，仅作为测试矩阵，不是对移动设备的容量承诺。

示例展示空间划分、遍历候选和最终 AABB 命中，明确这些与真实网格命中的区别。

## 7. 里程碑与后续路线

| 阶段 | 内容 | 完成依据 |
|---|---|---|
| M1：契约与正确性 | 几何、暴力基线、Double 静态对象树 | 契约落实，边界和随机对照通过 |
| M2：WASM 可用性 | 工作区复用、批量接口、容量状态、适配层 | wasm/wasm-gc 端到端验证及资源记录 |
| M3：首版交付 | 可交互示例、对照基准、文档和包 | Mooncakes 包、API 文档、测试、WASM 示例、基准和限制说明 |
| E1：单精度 | 实际单精度存储、转换规则、误差测试 | 对 Double 的内存、性能和正确性比较 |
| E2：动态对象索引 | 插入、删除、AABB 更新 | 与重建路线比较总成本和尾延迟 |
| E3：静态点云索引 | 三坐标存储、区域/半径/kNN 查询 | 专门的点云契约、暴力对照与基准 |
| E4：动态点云索引 | 点插入、删除、移动及维护 | 更新与查询组合负载下的正确性和资源验证 |

E1–E3 的先后可按实际接入需求调整，不要求并行开发；E4 建立在点云契约与实现经验之上。

动态写入是后续目标，具体使用 loose octree 与否由证据决定。在相同数据和查询下比较静态重建、动态 loose octree，以及适用的空间哈希或动态 BVH，记录更新加查询的总耗时、峰值内存、候选数量和尾延迟。

动态版本可以先支持固定根内的更新；自动扩根不是动态写入的必要前置条件。只读用户不应默认承担句柄映射、空闲链表和重定位成本。

## 8. 与早期设想的关系

现有代码只落实了 Double 的 Vec3；早期多用途、动态近邻、降采样、序列化、2:1 平衡等设想未形成实现。本方案优先建立对象索引，再独立扩展点云和动态类型。

降采样、序列化、2:1 平衡、概率占据和 GPU 能力不在已承诺的扩展路线内。将来如有需要，应单独论证，不因早期讨论或模块描述而自动进入范围。
